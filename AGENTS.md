# AGENTS.md

Notes for anyone working on this repo, human or AI. `README.md` explains what the project is and how to run it; `docs/SPEC.md` is the product spec, with an "As built" section for each feature that records what was decided and why. Read the relevant section before changing a feature.

## What this is

Food Tools: self-hosted calorie tracking, goals, recipes, meal planning and shopping lists, for the UK. An Expo (React Native) app talks to a TypeScript API and Postgres, run together with `docker compose up`.

## Layout

| Path | What it is |
| --- | --- |
| `apps/api` | Hono API, Better Auth, Drizzle ORM and migrations, vitest tests |
| `apps/api/src/routes` | HTTP routes (zod validation, `requireSession`) |
| `apps/api/src/{goals,recipes,planner,shopping}` | Pure logic for each area, with `*.test.ts` beside it |
| `apps/mobile` | Expo app. Screens are in `src/app` (Expo Router), components in `src/components`, API client in `src/lib/api.ts`, data hooks in `src/lib/queries.ts` |
| `docs/SPEC.md` | Product spec and as-built notes |

## Commands

```sh
npm install
npm run dev:db       # Postgres on localhost:5432
npm run dev:api      # API with reload on :3000
npm run dev:mobile   # Expo dev server
npm run typecheck && npm run lint && npm test   # run all three before finishing a change
docker compose up -d --build                     # the whole server stack
npm run db:generate -w apps/api                  # new migration after a schema change (applied when the API starts)
npm run build:cofid -w apps/api                  # rebuild the UK generic food data
```

Copy `.env.example` to `.env` for local settings. Never commit `.env`, `.env.local` or `.cache/`.

## Working here

- **Tickets are GitHub Issues**, grouped by milestone. Reference them in commits (`Fixes #12`). The default branch is `dev`.
- **Commit messages** start with a short imperative summary, then say why, not just what.
- **Put rules in pure functions with tests** (calories, fitting, matching, list building), and keep routes thin.
- **Finish what you change:** typecheck, lint and tests pass, and docs are updated if behaviour changed (add to the "As built" notes in `docs/SPEC.md`).
- **Say what you couldn't test.** Don't claim a screen works if you only checked the API.

## Conventions

- Nutrition is stored per 100 g. Weights are kg and heights cm in the database; units are only converted for display (`apps/mobile/src/lib/units.ts`).
- Dates are `YYYY-MM-DD` strings in the user's local day. Weeks start on Monday.
- Wording is neutral about food. No red "over" warnings, no guilt or streak language. Going over a target is shown as plain information.
- Diary entries keep a snapshot of nutrition at the time of logging. Plans and recipes use live nutrition.

## Gotchas

- **Start Expo from `apps/mobile`** (`npm run dev:mobile`), not the repo root. A stray `tsconfig.json` or `.expo/` at the root means it was started in the wrong place; delete them.
- **New Expo routes show type errors until the dev server has run**, because the typed routes are generated by it.
- **Expo's docs change between SDK versions.** Check `apps/mobile/AGENTS.md` and the versioned docs rather than trusting memory.
- **Food data has gaps.** CoFID has no cumin, oregano, paprika or chickpeas, and one food code (13-669) is used twice in the source spreadsheet (handled in `scripts/build-cofid.ts`).
- **Goals are versioned.** A new goal starts on a date; past days keep the targets that applied then.
- **Planned and eaten are separate.** A planned meal is eaten when it has a `logEntryId`. Deleting that diary entry makes it pending again.
- **The shopping list is derived from the plan on every read.** Only the user's choices are stored (ticks, pantry, pack sizes, aisles, product links). Leftovers are bought for with their cook.
- **Supermarket search addresses** are in `apps/api/src/shopping/links.ts`. The sites return 403 to scripts, so check them in a real browser. A search that lands on a home or category page means the format changed.
- **Anything on the server that fetches a user-supplied URL must use `recipes/fetch-page.ts`.** It blocks private and local addresses (SSRF), including after DNS lookups and redirects.
- **The diet check is a keyword match on ingredient names**, not an allergen guarantee. Don't describe it as safe for allergies.
- **Optional Claude recipe import** uses an API key (`ANTHROPIC_API_KEY`), not a subscription login: Anthropic doesn't allow third-party products to offer claude.ai login.
- **Test accounts:** when testing against a running stack, delete any user you create afterwards.
